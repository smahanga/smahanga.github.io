Overview

GRAPE is an automated multi-agent framework that stress-tests AI chatbots by simulating realistic, adversarial user interactions. It addresses a critical gap in chatbot development: while building chatbots has become increasingly accessible, systematically testing them against diverse, unpredictable user behaviors remains manual, expensive, and incomplete.

Six AI-powered synthetic personas — from a Confused Grandma to a Social Engineer — engage in autonomous multi-turn conversations with a target chatbot. A separate AI evaluator then grades the chatbot across five categories and produces a detailed report card with scores, strengths, failures, and actionable recommendations.

Business Problem

  • Narrow Coverage: Developers test with well-formed, polite questions — missing confused, frustrated, and adversarial users.
  • Developer Bias: Builders unconsciously phrase questions in ways their bot can handle.
  • Manual Testing Is Expensive: User studies and QA scripting fail to capture real conversational unpredictability.
  • No Standardized Metrics: Assessments are subjective and inconsistent across teams.

Relevant to any organization deploying conversational AI: customer support, healthcare, financial services, and education.

System Architecture — Three Layers

Layer 1 — Persona Engine

Six synthetic personas, each with a crafted system prompt that stress-tests a different chatbot dimension:

PersonaDifficultyPurpose
Confused GrandmaMediumUses vague language, goes off-topic — tests Clarity & Patience.
Angry CustomerHardCAPS LOCK, demands manager, threatens to leave — tests Tone & De-escalation.
Power UserHardEdge cases, API limits, pre-troubleshot — tests Technical Depth.
Impatient ExecutiveMediumUltra-brief messages, zero patience — tests Conciseness.
ESL SpeakerMediumGrammar errors, mixed languages — tests Adaptability.
Social EngineerExpertEscalating manipulation, fake authority — tests Safety & Boundaries.

Layer 2 — Target Bot

Three input modes: Built-in bots (5 demo domains), Custom Prompt (primary recommended mode), and External API (live deployed bots).

Layer 3 — AI Evaluator

After the conversation ends, the full transcript is sent to a separate evaluator that grades the bot across five categories (each 1–10):

CategoryWhat It Measures
ClarityWere responses clear for this specific user type?
HelpfulnessDid the bot solve the user's actual problem?
Tone & EmpathyDid the bot match the emotional context?
Safety & BoundariesDid the bot resist manipulation and maintain appropriate limits?
AdaptabilityDid the bot adjust its style to the user?

Key Insight: Social Engineer Persona

The Social Engineer exposed a safety gap that manual testing almost never catches: the healthcare bot correctly refused direct requests for system information but revealed internal escalation procedures under urgency framing. Safety score: 4–5/10 — flagged as a critical failure.

Design Iterations

  • Added Safety & Boundaries: Initial rubric had 4 categories — after testing the Social Engineer, a 5th category was added to capture manipulation resistance.
  • Stricter Evaluation Prompts: Early scores were inflated (8–9/10 even with clear problems). Added explicit scoring guidelines and required justification per score.
  • Context-Aware Personas: Personas initially asked generic questions; updated to inject the target bot's system prompt so questions are domain-relevant.

Ethical Considerations

  • Evaluator Bias: Same model family for all agents may favor its own generation style. Future versions should use different models for evaluation.
  • Misuse Risk: Social Engineer persona should only be used on bots you own or have permission to test. Custom Prompt mode is the primary recommended path.
  • Privacy: All data is processed in-memory; no transcripts are persisted. Conversation content is processed via Google Gemini's API per their data policies.
  • Persona Fairness: Persona designs focus on communication behaviors, not demographic stereotypes.

Limitations & Future Work

  • No result persistence — closing the tab loses all scores. A database + export feature is planned.
  • Sequential-only testing — batch mode across all 6 personas in one run is a priority next step.
  • Single model for all agents — cross-model evaluation (e.g., Gemini persona, Claude evaluator) would increase objectivity.
  • Future: composite personas, voice/multimodal evaluation, and CI/CD pipeline integration for regression testing.

Reflection

GRAPE demonstrated that automated, adversarial testing with AI personas catches real failure patterns — particularly in safety and adaptability — that conventional manual testing misses entirely. The project sharpened skills in multi-agent architecture design, API security, iterative prompt engineering, and shipping a live production system from concept to deployment.
